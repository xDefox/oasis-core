# Quickstart

> Пять команд до первого шага в мире. Если на этом пути что-то сломалось —
> это баг онбординга, а не ваша проблема. Заводите issue.

Требуется: **Node.js ≥ 22** (рекомендуем 24 LTS) и npm 10+. Docker **не нужен**.

Проверьте версию:

```bash
node -v   # должно быть v22+ или v24+
npm -v
```

Если `node` не находится в **новом** окне терминала, а в IDE находится —
Node не в системном PATH (частая беда на Windows: раздутый PATH обрезается,
и `cmd` не видит `node.exe`). Добавьте каталог с `node.exe` в PATH пользователя
и **откройте новый** терминал. Портативная сборка с [nodejs.org](https://nodejs.org/)
(zip) тоже подходит: достаточно прописать её папку в PATH.

---

## 1. Клон и установка

```bash
git clone https://github.com/xDefox/oasis-core.git
cd oasis-core
npm install
```

Если `npm install` падает на `esbuild` с ошибкой вроде
`"node" не является внутренней или внешней командой` — это снова PATH:
скрипт установки запускается через `cmd` и не видит Node. Почините PATH,
закройте процессы, держащие `node_modules` (IDE/антивирус), удалите
`node_modules` и повторите:

```bash
# Windows PowerShell
Remove-Item -Recurse -Force node_modules -ErrorAction SilentlyContinue
npm install
```

> Команды `npm install-scripts approve …` в обычном npm **нет**. Если где-то
> встретите её в старых заметках — игнорируйте.

---

## 2. Запуск

```bash
npm run dev
```

Поднимаются два процесса с цветными префиксами:

```
[server] [oasis] ledger: memory (режим разработки)
[server] [oasis] сервер поднят { url: 'http://0.0.0.0:2567', … }
[client]   VITE v8  ready in 300 ms
[client]   ➜  Local:   http://localhost:5173/
```

Откройте **http://localhost:5173**. Клик по сцене — захват мыши.

Если порт 5173 занят (`Port 5173 is already in use`) — остановите старый
`npm run dev` или процесс на этом порту и запустите снова.

**Второй игрок в той же сети:** откройте на другом компе
`http://<IP-хоста>:5173/` (Vite печатает Network-адрес). Клиент сам
подключится к `ws://<тот-же-хост>:2567`.

## 3. Управление

| Клавиша | Действие |
|---|---|
| `WASD` / стрелки | движение |
| `Shift` | бег |
| мышь | обзор (после клика по сцене) |
| `Enter` | чат |
| `Esc` | закрыть чат |
| `Tab` | освободить курсор |
| `/name <ник>` | сменить ник (вводится в чат) |
| `/help` | список команд |
| `!gather` | собрать ближайший узел добычи (слизня в радиусе 3 м) |
| `!pay <ник> <сумма>` | перевести деньги; свыше 1000 ¤ сгорает 5 % комиссии |

`!` — это временный мост: клиент перехватывает текст с `/` и не отправляет
его на сервер, а `!` пропускает как обычный текст, и сервер отрезает его
до общего чата (docs/10 §8.2). `/gather` и `/pay` сервер тоже принимает —
они заработают, когда клиент научится пересылать неизвестные команды.

## 4. Проверка, что это действительно мир

1. Откройте вторую вкладку (или второе окно) на том же адресе.
2. Если ник совпал (две вкладки одного профиля делят `localStorage`), сервер
   разведёт его суффиксом: вторая вкладка станет `<ник> (2)`. Клиент напишет
   об этом в чат. Сменить ник вручную: `/name моё-имя`.
3. Оба аватара должны быть видны друг другу, двигаться и поворачиваться.
4. Напишите в чат из одной вкладки — сообщение должно появиться в обеих.
5. Отойдите от спавна на пару метров — там зелёный слизень-узел. `!gather`
   в чате: сервер начислит 3 ¤ и скажет, когда узел можно собрать снова.
6. Из первой вкладки: `!pay <ник второй вкладки> 10` — вторая получит
   уведомление и 10 ¤ (до 1000 ¤ комиссии нет, свыше сгорает 5 %).
7. Дойдите до светящегося кольца — сервер телепортирует в соседнюю зону.
   Старая зона выгружается из памяти клиента (в сцене остаётся одна).

Если пункт 3 не работает — смотрите вкладку Network: должен идти бинарный
поток на `ws://localhost:2567`. Если пусто — смотрите консоль сервера.

## 5. Проверки без браузера

```bash
npm run typecheck   # tsc по трём пакетам
npm test            # 98 тестов в 11 файлах: от кодека до живого сервера с клиентом
```

`npm test` поднимает настоящий Colyseus — интеграционные тесты сидят на порту
2620, тест авторизации на 2621 — и подключаются к нему через `@colyseus/sdk`.
Если порт занят — остановите другой экземпляр сервера.

## 6. Публичная ссылка: деплой одной командой

Чтобы зайти со своего телефона или с чужой машины — без проброса портов,
домена и аккаунта:

```bash
bash scripts/deploy.sh        # сервер + туннель + сборка клиента → печатает ссылку
node scripts/deploy-check.mjs # проверить, что по ссылке реально играют
```

Что делает `deploy.sh`: поднимает сервер на 2567, поднимает туннель и ждёт
от него адрес, пишет этот адрес в `packages/client/.env.production`, собирает
клиент и печатает ссылку. Отдельная статика не нужна: если существует
`packages/client/dist/index.html`, сервер отдаёт клиент сам.

Перед стартом скрипт готовит auth-lite (F0-6/F0-7): один раз генерирует
`OASIS_AUTH_SECRET` в `.env` и поднимает сервер с `NODE_ENV=production`.
Это и есть закрытие D-009 — без подписанной cookie вход закрыт, а клиент
берёт её на `GET /auth/session` до подключения по вебсокету.

Грабли, о которых стоит знать заранее:

- первый запуск создаёт `.env` с секретом подписи сессий: не удалять и не
  коммитить (файл в `.gitignore`) — без него кука подписывается общим
  dev-ключом из исходника, и подделать её сможет любой, кто читал репозиторий;
- если после обновления никто не может войти — откатить строгий режим одной
  командой: `NODE_ENV=development bash scripts/deploy.sh`;

- туннель выбирается сам: сначала serveo, если есть ключ
  `~/.ssh/serveo_key` — это и есть постоянный адрес; иначе cloudflare, а
  через 15 секунд без адреса — pinggy. Принудительно: `TUNNEL=pinggy bash scripts/deploy.sh`;
- **адрес постоянный** (F1-17 закрыт 27.10, PR #16): имя «oasis-play»
  закреплено за SSH-ключом, перезапуск `deploy.sh` даёт ту же ссылку.
  Живёт адрес, пока жив ssh-туннель: если страница вдруг отдаёт 502 —
  просто запустите `deploy.sh` заново, ссылка не изменится. У
  quick-туннелей (cloudflare, pinggy) адрес по-прежнему новый при каждом
  запуске;
- у pinggy перед игрой страница предупреждения: нажать **«Enter site»**.
  При перезагрузке страницы кнопку просят нажать снова, уже открытая игра
  при этом не рвётся;
- остановить деплой (все три туннеля; скобки в паттерне — чтобы pkill не
  убил сам себя):

```bash
lsof -ti:2567 | xargs -r kill -9
pkill -f '[s]erveo.net'; pkill -f '[c]loudflared tunnel'; pkill -f '[a].pinggy.io'
```

Подробности — почему один домен обязателен, как обходится заблокированный
адрес cloudflare и какие туннелы проверены и отвергнуты — в
`docs/13-deploy-tunnel.md`.

## Если хочется с Postgres

По умолчанию ledger в памяти: перезапуск сервера = мир с нуля. Это осознанно
(быстрый онбординг). Для персистентности:

```bash
docker compose up -d
STORAGE=postgres npm run dev -w @oasis/server
```

Миграции применяются автоматически при старте. Если `docker compose` отвечает
`permission denied` на `/var/run/docker.sock` — ваш пользователь не в группе
`docker`; это локальная проблема окружения, на код не влияет.

## Если хочется перегенерировать мир

```bash
npm run generate:world -w @oasis/server
```

Генератор детерминированный: один и тот же `seed` даёт один и тот же мир.
Меняете seed в `packages/server/scripts/generate-world.ts` — получаете другой
мир с теми же правилами.
